## Intuition

A **[queue](/glossary#queue)** is a line at a coffee shop. You join at the **back**, and the barista serves from the **front**. Whoever has waited longest is served next — no cutting in line. That is the opposite of a stack: a queue is **[FIFO](/glossary#fifo)**, "first in, first out."

The two operations are **enqueue** (join at the rear) and **dequeue** (leave from the front). Because the two ends are different, a queue naturally preserves arrival order — which is exactly what you want for a print spooler, a task scheduler, or the "to visit" list in a breadth-first search.

There is a clever storage trick worth meeting early. If we keep the queue in a fixed array and just move the front index forward on each dequeue, the used region drifts rightward and eventually the front bumps into the end — even though the freed slots at the start are sitting empty. A **circular queue** (or **ring buffer**) fixes this by letting the rear **wrap around** to index 0, reusing those freed slots. The array is finite, but we treat it as if its ends were joined into a ring.

## How it works

The visualization always draws all the fixed slots, so you can see the ring's capacity. Empty slots show a dim `·`; the **front** and **rear** carets mark the live ends.

1. **Enqueue** — write the value at the next rear position, computed as `(head + size) % capacity`. The `% capacity` is what makes the index wrap back to the start when it runs off the end. **O(1)**.
2. **Dequeue** — read the value at `head`, clear that slot, and advance `head` by one (again with `% capacity`). **O(1)**.

Step through the demo: it enqueues a few values, dequeues a couple — advancing the front and freeing early slots — then enqueues more until the rear **wraps around** to reuse slot 0. A dashed arc appears when the occupied run wraps past the end.

## Common pitfalls

<Callout variant="warning">
  Track the queue's **size** (or a separate full/empty flag). With only a head
  and a rear index, a completely full ring and a completely empty ring can look
  identical — head and rear land on the same slot in both cases.
</Callout>

<Collapsible summary="Don't dequeue from the wrong end">
  Enqueue must add at the rear and dequeue must remove from the front. Swap them
  and you get a stack (LIFO), not a queue. The two different ends are what make
  a queue first-in, first-out.
</Collapsible>

<Collapsible summary="A plain array queue can waste space or go O(n)">
  If you dequeue by shifting every element left, each dequeue is O(n). If
  instead you just advance a front index without wrapping, the freed front slots
  are wasted and the queue "walks off" the end of the array. The circular buffer
  solves both problems at once.
</Collapsible>

<Collapsible summary="Handling a full queue">
  A fixed ring has no room once `size == capacity`. Decide the policy up front:
  reject the enqueue (raise/return an error), overwrite the oldest item (a
  common choice for streaming buffers), or grow to a larger array and copy
  everything over (an occasional O(n) resize, like a dynamic array).
</Collapsible>

## Practice

Work each one out before opening the answer.

**1. You enqueue 1, 2, 3 into an empty queue, then dequeue once. What value leaves, and how does that differ from a stack?**

<PracticeCheck slug={frontmatter.slug} index={1} total={3}>
  1 leaves. A queue is FIFO — first in, first out — so the earliest arrival goes
  first. A stack (LIFO) would have removed 3, the most recent.
</PracticeCheck>

**2. In a circular queue of capacity 5 with `head = 3` and `size = 4`, at which index does the next enqueue write?**

<PracticeCheck slug={frontmatter.slug} index={2} total={3}>
  Index 2. The rear is `(head + size) % capacity = (3 + 4) % 5 = 7 % 5 = 2`. The
  index wrapped past the end of the array and back to the start — the circular
  trick at work.
</PracticeCheck>

**3. Why does a circular queue use `% capacity` when moving the head and rear?**

<PracticeCheck slug={frontmatter.slug} index={3} total={3}>
  The modulo wraps an index back to 0 once it reaches the end of the fixed
  array, so freed slots at the front get reused instead of wasted. Without it,
  the indices would run off the end and the queue could not reuse space.
</PracticeCheck>
