## Intuition

Think of a stack of dinner plates. You add a clean plate to the **top** of the pile, and when you need one you take it from the **top** too. You never pull a plate out of the middle — the whole tower would topple. So the plate you grab is always the one you added most recently.

That is a **[stack](/glossary#stack)**: a collection with one rule — **[LIFO](/glossary#lifo)**, "last in, first out." The most recently added item is the first one to leave. Only the top is ever touched, which is exactly why a stack is so fast and so simple.

The two operations have traditional names: **push** (add an item on top) and **pop** (remove the top item). A third, **peek**, looks at the top without removing it.

## How it works

The visualization draws the stack vertically, index 0 at the bottom, the newest item on top. A **top** caret always marks where the action happens.

1. **Push** — place the new value on top. Because we only ever add at the top, nothing below moves. **O(1)**.
2. **Pop** — remove the top value. Again nothing below moves. **O(1)**.

Because the last item pushed sits on top, it is the first one popped. Watch the demo build the stack up by pushing several values, then tear it down by popping — the values come off in the exact reverse of the order they went on. That reversal is LIFO in action.

Press **Play**, or **Step forward** one operation at a time. The `+` marks a push, the `✕` marks a pop, and the **top** caret follows the top of the stack. Enter your own values to push — then watch them pop off in reverse.

## Common pitfalls

<Callout variant="warning">
  Always check whether the stack is empty before you pop or peek. Popping an
  empty stack is a classic bug — decide up front whether it should raise an
  error or return a sentinel, and be consistent.
</Callout>

<Collapsible summary="Where stacks show up">
  Stacks are everywhere: the **call stack** that tracks function calls, the
  **undo** history in an editor, the back button's page history, and matching
  brackets in a compiler. Any time you need "most recent first," reach for a
  stack.
</Collapsible>

<Collapsible summary="Push and pop must use the same end">
  A stack is only O(1) because both operations happen at the same end of the
  underlying storage — the end, where no shifting is needed. If you pushed to
  the end but popped from the front of a plain array, every pop would shift all
  n elements and become O(n). Keep both at the top.
</Collapsible>

<Collapsible summary="Stack overflow is a real limit">
  The program's call stack has a fixed size. Deep or infinite recursion keeps
  pushing frames without popping them, eventually exhausting that space — the
  famous "stack overflow" crash. It is the same LIFO structure, just managed by
  the language runtime.
</Collapsible>

## Practice

Work each one out before opening the answer.

**1. You push 1, 2, then 3 onto an empty stack, then pop once. What value comes off, and why?**

<PracticeCheck slug={frontmatter.slug} index={1} total={3}>
  3. A stack is LIFO — last in, first out — and 3 was pushed most recently, so
  it sits on top and is popped first.
</PracticeCheck>

**2. Why are both push and pop O(1) rather than O(n)?**

<PracticeCheck slug={frontmatter.slug} index={2} total={3}>
  Both touch only the top of the stack. Nothing below the top ever moves, so the
  cost does not depend on how many items the stack holds — it is constant, O(1).
</PracticeCheck>

**3. You push A, B, C, D. What sequence of pops returns them in the order D, C, B, A — and could a stack ever return them as A, B, C, D?**

<PracticeCheck slug={frontmatter.slug} index={3} total={3}>
  Four pops in a row give D, C, B, A — the reverse of insertion order, which is
  exactly what LIFO produces. Getting A, B, C, D back would require removing the
  bottom item first, which a stack cannot do; that is a queue's job.
</PracticeCheck>
